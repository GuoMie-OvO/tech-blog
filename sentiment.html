产品问题

金融信息既来自文章，也来自视频。一篇报道可能涉及多只股票与多个行业；如果只给整篇文章一个标签，难以回答“对哪只股票、哪个行业有什么影响”。

我的工作

将内容接入、特征整理、情感研判、逐股与行业分析、统计接口和展示串成完整链路；把来源可追溯、样本可理解、数据可持续更新作为产品设计要求。

产品结果

从原始内容形成结构化分析，再提供市场、行业与个股三个视角。用户可以从概览进入具体股票、相关报道和来源页面，检查判断的依据。

文章与视频，走进同一条分析链路。

  1. 接入与整理

    只读获取上游内容，提取标题、原文、来源链接、关键词、实体、股票和行业关联，写入本地数据库。

  2. 去重与规范化

    聚合统计使用规范化标题与内容哈希识别重复内容，并按时间窗口分组，减少转载对报道量与榜单的重复放大。

  3. 视频转文字

    对视频链接进行金融相关性审核，通过后提取音轨并转写。保留来源和转写信息，将原记录升级为视频内容，避免新增一份重复报道。

  4. 语义与对象研判

    生成文章情感，再围绕股票与行业分析具体影响、相关性和理由。符合条件的短文复用联合结果，其余内容交由独立处理链路完成。

  5. 统计与对外供给

    分析结果写入本地 PostgreSQL，经只读 API 供市场大盘、个股详情、行业统计与下游工具消费。

三个视角，服务不同的研究问题。

市场：整体在发生什么？

去重报道量、已研判覆盖率、情感构成、市场情绪、报道趋势、热门股票、来源与最新报道。

行业：影响落在哪里？

独立行业研判、行业排行、情绪与相关报道。从行业层面定位事件影响，不将整篇情感标签直接当作行业结论。

个股：与这只股票有什么关系？

逐股研判、情感构成、报道占比、热词、传播来源与相关报道；可以打开原文检查依据。

样本：这份判断有多少依据？

区分未研判与已研判；正向候选结合样本量、平滑比例和稳健排序，展示实际统计区间与少样本提示。

清晰的口径，才有可用的结论。

市场趋势把报道量和 3 日滚动净情绪分开呈现。滚动净情绪先汇总窗口内的利好与利空，再计算差值比例；没有有效样本时保留缺失，避免将“无数据”误写成“情绪中性”。

当日值、区间值与累计快照分别使用；情感构成以已研判报道为分母，累计点击与播放保留来源口径。页面通过快照版本、缓存与后台更新保持阅读连续性。

部署形态、持续运行与产品边界 ＋

前端与数据服务可在客户环境部署，模型服务支持本机 Ollama 或远程兼容接口。远程推理会发送用于分析的文本，不能将这种形态描述为所有数据始终不出网。

视频采用持久任务队列，下载或临时失败会重试，中断任务在重启后重新入队；分析 Worker 记录处理状态、模型版本、理由与失败信息，便于持续维护。

舆情围绕最近 90 日滚动处理，这是已确定的运营策略，不表述为代码硬性自动清理保证。产品统计保留明确的日期区间、研判覆盖与模型版本，不以持续增长的累计入库量代替实际产品能力。

上游原始内容读取与本地分析结果写入相互分离；系统使用 FastAPI、PostgreSQL、Python Worker 与语音转写组件，结果通过只读查询接口供给其他系统。
